# ヒープ（Heap）とは

ヒープは「完全二分木」の一種で、各ノードの値がその子ノードの値以上（最大ヒープ）または以下（最小ヒープ）となるように構成されるデータ構造。主に**優先度付きキュー**や**ヒープソート**などで利用される。

**このデータ構造の最大の利点は、最小値（または最大値）の高速な取得・削除・挿入が可能な点である。**

# ヒープの構成要素

- **ノード（Node）**: データを保持する単位。親・子の関係を持つ。
- **ルート（Root）**: 最上位のノード。最小ヒープなら最小値、最大ヒープなら最大値を持つ。
- **エッジ（Edge）**: 親子ノードを結ぶ線。
- **葉（Leaf）**: 子ノードを持たないノード。
- **完全二分木**: 全てのレベルが左詰めで埋まっている二分木であり、高さが O(log n)に保たれる。

# ヒープの種類

- **最小ヒープ（Min Heap）**: 親 ≤ 子。ルートが最小値。
- **最大ヒープ（Max Heap）**: 親 ≥ 子。ルートが最大値。
- **二項ヒープ・フィボナッチヒープ**: より高度なヒープ構造（主に理論・特殊用途）。

# 二項ヒープ・フィボナッチヒープ

## 二項ヒープ（Binomial Heap）

### 概要

二項ヒープは複数の**二項木**（Binomial Tree）の集合として構成される高度なヒープ構造。通常の二分ヒープよりも複雑だが、特にヒープの結合（merge）操作で優れた性能を発揮する。

### 二項木の特徴

```
B₀:  ●

B₁:  ●
     │
     ●


B₂:  ●
    ╱ ╲
   ●   ●
   │
   ●

B₃:    ●
      ╱ ╲
     ●   ●
    ╱ ╲   │
   ●   ●  ●
   │      │
   ●
```

- **B_k**: k 次の二項木（2^k 個のノードを持つ）
- **構造**: B*k は B*{k-1} を 2 つ結合して作成
- **子の数**: ルートノードは k 個の子を持つ
- **高さ**: k（レベル数は k+1）

### 二項ヒープの性質

1. **ヒープ条件**: 各二項木で親 ≤ 子（最小ヒープの場合）
2. **二項木の順序**: 次数の昇順で配列
3. **一意性**: 各次数の二項木は最大 1 つまで
4. **ルートリスト**: 各二項木のルートを連結リストで管理

## フィボナッチヒープ（Fibonacci Heap）

### 概要

フィボナッチヒープは**償却計算量**の観点で最も効率的なヒープ構造の一つ。特にグラフアルゴリズム（ダイクストラ法、プリム法）で威力を発揮するが、実装が非常に複雑。

### 構造の特徴

```
ルートリスト（循環連結リスト）:
    [10] ←→ [15] ←→ [8] ←→ [25]
     │       │      │      │
   [20]    [18]   [12]   [30]
     │       │      │
   [25]    [22]   [14]
                     │
                   [16]
```

- **ルートリスト**: すべてのルートノードを循環連結リストで管理
- **任意の木構造**: 各ノードは任意数の子を持てる
- **マーク**: ノードが子を失ったかどうかの印（削除の効率化）
- **最小ポインタ**: 最小値ノードへの直接参照

### フィボナッチ数列との関係

```
フィボナッチ数列: F₀=0, F₁=1, F₂=1, F₃=2, F₄=3, F₅=5, F₆=8, ...

次数 k のノードが持つ最小子ノード数 ≥ F_{k+2} - 1

これにより、n 個のノードを持つヒープの最大次数は O(log n) に制限される
```

## 使用場面

### 二項ヒープが適している場面

- **頻繁なヒープ結合**: 複数の優先度付きキューをマージする場合
- **分散システム**: 異なるノードのヒープを統合
- **並列処理**: ワーカー間でタスクキューを結合
- **メモリ効率**: 通常のヒープより少ないメモリ使用量

### フィボナッチヒープが適している場面

- **グラフアルゴリズム**: ダイクストラ法、プリム法での理論的最適性
- **DecreaseKey 頻発**: キー値の減少操作が非常に頻繁
- **理論研究**: アルゴリズムの理論的下界の証明
- **学術用途**: 計算量理論の研究

## まとめ

### 二項ヒープ

- **利点**: 効率的なマージ操作、理論的に美しい構造
- **欠点**: 実装が複雑、FindMin が O(log n)
- **適用**: ヒープの結合が頻繁な場合

### フィボナッチヒープ

- **利点**: 理論的に最適な償却計算量
- **欠点**: 実装が非常に複雑、定数項が大きい
- **適用**: 主に理論研究、特殊なグラフアルゴリズム

### 実用的な選択指針

1. **一般用途**: 二分ヒープ（配列実装）
2. **頻繁なマージ**: 二項ヒープ
3. **理論的最適性**: フィボナッチヒープ
4. **実装簡易性**: 二分ヒープ

# ヒープの特徴

- **最小/最大値の取得**: O(1)
- **挿入・削除**: O(log n)
- **完全二分木**: 配列で効率的に実装可能
- **順序走査や範囲検索は苦手**: ヒープ中の全てのノードを探索する必要があり、O(n)かかる
  - 「最小/最大値の取得」に加えて「値の検索」も必要なら、平衡二分探索木を用いる

# ヒープと優先度付きキュー

- **ヒープ**
  - **特徴**: データ構造そのもの。完全二分木の特徴を持ち、全ての親ノード・子ノードのペアに対して、親ノードの値が子ノードよりも小さい（最小ヒープ）、または大きい（最大ヒープ）。
  - **用途**: ヒープソート、優先度付きキュー、グラフアルゴリズムでの利用（例: ダイクストラ法、プライム法）
- **優先度付きキュー**
  - **特徴**: 抽象データ型。各要素に優先度を持たせ、ルートノードに優先度が一番高いデータを保存し、高速に取り出せる。
  - **実装**: ヒープが多い。配列や連結リストでも実装可能。
  - **用途**: タスクスケジューリング、イベント駆動システム、グラフアルゴリズム（例: ダイクストラ法、プライム法）

# ヒープの一般的な実装方法

## 配列による実装

ヒープは木構造であるが、ポインタを使わずに配列（またはスライス）を用いて効率的に実装できる。親子ノードの関係は配列のインデックス間の計算で表現できる。

- ノードを配列で管理し、インデックスで親子関係を計算
  - 親: `(i-1)/2`
  - 左子: `2i+1`
  - 右子: `2i+2`
- メモリ効率・キャッシュ効率が高い
- 動的サイズ変更も容易

## Go による最小ヒープの実装例

ライブラリを用いずに、自前で最小ヒープを実装する。

```go
package heap

type MinHeap struct {
    data []int
}

func NewMinHeap() *MinHeap {
    return &MinHeap{data: []int{}}
}

func (h *MinHeap) Insert(val int) {
    h.data = append(h.data, val)
    h.upHeap(len(h.data) - 1)
}

func (h *MinHeap) upHeap(i int) {
    for i > 0 {
        parent := (i - 1) / 2
        if h.data[parent] <= h.data[i] {
            break
        }
        h.data[parent], h.data[i] = h.data[i], h.data[parent]
        i = parent
    }
}

func (h *MinHeap) ExtractMin() (int, bool) {
    if len(h.data) == 0 {
        return 0, false
    }
    min := h.data[0]
    last := h.data[len(h.data)-1]
    h.data = h.data[:len(h.data)-1]
    if len(h.data) > 0 {
        h.data[0] = last
        h.downHeap(0)
    }
    return min, true
}

func (h *MinHeap) downHeap(i int) {
    n := len(h.data)
    for {
        left := 2*i + 1
        right := 2*i + 2
        smallest := i
        if left < n && h.data[left] < h.data[smallest] {
            smallest = left
        }
        if right < n && h.data[right] < h.data[smallest] {
            smallest = right
        }
        if smallest == i {
            break
        }
        h.data[i], h.data[smallest] = h.data[smallest], h.data[i]
        i = smallest
    }
}

func (h *MinHeap) Peek() (int, bool) {
    if len(h.data) == 0 {
        return 0, false
    }
    return h.data[0], true
}
```

## Go による最大ヒープの実装例

`container/heap` パッケージを使用して最大ヒープを実装する例。
優先度の高い要素を効率的に管理できる。

```go
package main

import (
    "container/heap"
    "fmt"
)

// Item はヒープ内の要素を表す
type Item struct {
    value    string // 要素の値
    priority int    // 優先度（大きいほど優先される）
}

// MaxHeap は最大ヒープを表す
type MaxHeap []*Item

// Len はヒープの長さを返す
func (h MaxHeap) Len() int { return len(h) }

// Less は優先度を比較する（大きい値が優先される）
func (h MaxHeap) Less(i, j int) bool {
    return h[i].priority > h[j].priority
}

// Swap はヒープ内の要素を交換する
func (h MaxHeap) Swap(i, j int) {
    h[i], h[j] = h[j], h[i]
}

// Push はヒープに新しい要素を追加する
func (h *MaxHeap) Push(x interface{}) {
    *h = append(*h, x.(*Item))
}

// Pop はヒープから最優先の要素を取り出す
func (h *MaxHeap) Pop() interface{} {
    old := *h
    n := len(old)
    item := old[n-1]
    *h = old[0 : n-1]
    return item
}

func main() {
    // 最大ヒープを初期化
    h := &MaxHeap{}
    heap.Init(h)

    // 要素を追加
    heap.Push(h, &Item{value: "task1", priority: 3})
    heap.Push(h, &Item{value: "task2", priority: 5})
    heap.Push(h, &Item{value: "task3", priority: 1})

    // ヒープから要素を取り出し
    for h.Len() > 0 {
        item := heap.Pop(h).(*Item)
        fmt.Printf("Value: %s, Priority: %d\n", item.value, item.priority)
    }
}
```

実行結果

```
Value: task2, Priority: 5
Value: task1, Priority: 3
Value: task3, Priority: 1
```

# 優先度付きキュー（Priority Queue）とは

優先度付きキューは、各要素に「優先度」を持たせ、常に最も優先度の高い（または低い）要素を高速に取り出せる抽象データ型である。
ヒープは優先度付きキューの実装に最適。

## 優先度付きキューの一般的な実装

- **ヒープ（配列実装）**: 挿入・削除ともに O(log n)、最小/最大値の取得が O(1)
- **連結リストや配列**: 挿入または削除が O(n) となり非効率
- **Go の標準ライブラリ**: `container/heap` パッケージで汎用ヒープをサポート

## Go による優先度付きキューの実装例

Go では`container/heap`を使うのが一般的で、ヒープ操作のインターフェースを提供している。
これにより、任意のデータ方をヒープとして扱うことができる。

以下は最小ヒープによる優先度付きキューの例である。

```go
package main

import (
    "container/heap"
    "fmt"
)

type Item struct {
    value    string
    priority int
}

type PriorityQueue []*Item

// コレクションの要素数を返す
func (pq PriorityQueue) Len() int { return len(pq) }

// i番目の要素が j番目より前にあるべきかを返す
func (pq PriorityQueue) Less(i, j int) bool {
    return pq[i].priority < pq[j].priority // 最小ヒープ
}
func (pq PriorityQueue) Swap(i, j int) {
    pq[i], pq[j] = pq[j], pq[i]
}

// ヒープ操作のためのメソッド
func (pq *PriorityQueue) Push(x interface{}) {
    *pq = append(*pq, x.(*Item))
}

// ヒープ操作のためのメソッド
func (pq *PriorityQueue) Pop() interface{} {
    old := *pq
    n := len(old)
    item := old[n-1]
    *pq = old[0 : n-1]
    return item
}

func main() {
    pq := &PriorityQueue{}
    heap.Init(pq)
    heap.Push(pq, &Item{value: "task1", priority: 3})
    heap.Push(pq, &Item{value: "task2", priority: 1})
    heap.Push(pq, &Item{value: "task3", priority: 2})

    for pq.Len() > 0 {
        item := heap.Pop(pq).(*Item)
        fmt.Println(item.value, item.priority)
    }
}
```

# ヒープの応用例

## 1. ソートアルゴリズム・ヒープソート

- **ヒープソート**: 配列をヒープ化してから順次最小/最大値を取り出すソート
- **時間計算量**: O(n log n) - 安定した性能
- **空間計算量**: O(1) - インプレースソート
- **特徴**: 最悪ケースでも O(n log n) が保証される

## 2. 選択問題・k 番目の要素取得

- **k 番目に小さい要素**: 最小ヒープで k 回 ExtractMin を実行
- **k 番目に大きい要素**: 最大ヒープで k 回 ExtractMax を実行
- **トップ k 問題**: 大量データから上位 k 件を効率的に取得
- **メディアン取得**: 2 つのヒープ（最小・最大）を組み合わせて中央値を維持

## 3. グラフアルゴリズム

- **ダイクストラ法**: 最短経路探索で未訪問ノードの距離管理
- **プリム法**: 最小全域木構築でエッジの重み管理
- **A\*アルゴリズム**: 経路探索でのヒューリスティック値管理
- **ハフマン符号化**: 文字頻度に基づく最適符号生成

## 4. データストリーム処理

- **リアルタイム統計**: ストリーミングデータの最小/最大値維持
- **移動窓最小/最大**: 時系列データの窓関数処理
- **オンライン選択**: データ到着順での k 番目要素管理
- **イベント処理**: タイムスタンプ順のイベント管理

## 5. メモリ管理・システムプログラミング

- **メモリプール**: 空きメモリブロックサイズの管理
- **ページ交換アルゴリズム**: LRU 近似でのページ優先度管理
- **ガベージコレクション**: オブジェクトの生存時間管理
- **キャッシュ管理**: アクセス頻度に基づくデータ管理

# 優先度付きキューの応用例

- **探索アルゴリズム**: グラフの最短経路を探索するアルゴリズムで、次に訪れるべきノード（現在のノードから最も低いコストでアクセスできるノード）を効率的に選択できる
- **ヒープソート**: ソートアルゴリズムの一つで、配列をヒープ化して、根から要素を一つずつ取り出して配列の後方に配置することでソートを実行するアルゴリズム。O(n log n)でインプレース（追加のメモリ領域なしに）ソートを行う。
- **システム**: 優先度の異なるジョブを管理するタスクスケジューラや、イベント駆動型シミュレーションなどで利用。

# ヒープ構造と探索アルゴリズム

ヒープは「最小値（または最大値）」の高速な取得・削除・挿入が可能なデータ構造。
この特性を活かして、探索アルゴリズムの中で「次に探索すべきノード」や「最もコストが小さいノード」を効率的に管理できる。

## 代表的な探索アルゴリズムとヒープの利用例

### ダイクストラ法（最短経路探索）

- **用途**: グラフ上で始点から各ノードへの最短経路を求める
- **ヒープの役割**: 未確定ノードの中から「最小コスト」のノードを優先的に取り出すために最小ヒープ（優先度付きキュー）を利用
- **効果**: 各ステップで O(log n)で最小コストノードを取得でき、全体の計算量を効率化

### プリム法（最小全域木）

- **用途**: グラフから全てのノードを含む最小コストの木を作る
- **ヒープの役割**: 未選択エッジの中から「最小コスト」のエッジを優先的に選ぶために最小ヒープを利用

### A\*アルゴリズム（経路探索）

- **用途**: スタートからゴールまでの最短経路をヒューリスティックを使って探索
- **ヒープの役割**: 評価値（コスト＋ヒューリスティック）が最小のノードを優先的に探索するために最小ヒープを利用

## ヒープを使うメリット

- **最小/最大値の高速取得**: 探索の「次の候補」を効率的に選べる
- **挿入・削除も高速**: 探索中に候補ノードが増減しても効率的に管理できる
- **大規模グラフでも実用的**: O(log n)で管理できるため、ノード数が多くても現実的な速度を維持

# ヒープが最適な場面と避けるべき場面

## ✅ ヒープが最適な場面

- **優先度付きキュー**: 最小/最大値の高速取得が必要
- **タスクスケジューリング**: 優先度に基づく処理順序制御
- **ヒープソート**: O(n log n)の安定したソート性能
- **グラフアルゴリズム**: ダイクストラ法、プリム法での距離管理
- **イベント駆動システム**: 時刻順のイベント処理
- **リアルタイム処理**: 最悪ケース性能保証が必要
- **メモリ制約環境**: 最小メモリでの効率的処理

## ❌ ヒープを避けるべき場面

- **一般的な検索**: O(n)で非効率
- **範囲クエリ**: 範囲検索が主目的
- **順序走査**: ソート済み順序での全要素取得
- **ランダムアクセス**: インデックスによる直接アクセス
- **文字列処理**: プレフィックス検索やパターンマッチング
- **関係性管理**: ノード間の複雑な関係表現
- **頻繁な検索**: 特定要素の存在確認が主目的

# まとめ

- ヒープは完全二分木を配列で実装し、最小/最大値の高速な取得・削除・挿入が可能
- 優先度付きキューはヒープで効率的に実装できる
- Go では`container/heap`パッケージを使うことで、柔軟な優先度付きキューを簡単に実装できる
