# スタック（Stack）とは

スタックは、LIFO（Last In, First Out：後入れ先出し）の原則に従ってデータを管理する線形データ構造です。最後に追加された要素が最初に取り出される特性を持ちます。

**最大の利点は、要素の追加・削除・参照がすべて O(1)の一定時間で実行できることです。** この高速性により、関数呼び出しの管理、式の評価、深度優先探索など、多くのアルゴリズムの基盤として活用されています。

## 基本的な特徴

- **LIFO 原則**: 最後に入れたものが最初に出る
- **単一アクセスポイント**: トップ（先頭）からのみアクセス可能
- **動的サイズ**: 実行時にサイズを変更可能
- **順序性**: 要素の挿入順序を逆順で取り出す
- **制限されたアクセス**: 中間要素への直接アクセス不可

## スタックの概念図

```
    ↓ push(要素の追加)・↑ pop（要素の取り出し）
┌─────────┐
│    4    │ ← top（トップ）
├─────────┤
│    3    │
├─────────┤
│    2    │
├─────────┤
│    1    │ ← bottom（ボトム）
└─────────┘

```

# 注意点

## サイズ制限のない成長

- **メモリ**: 無制限に成長する可能性
- **スタックオーバーフロー**: メモリ不足や再帰の深すぎる呼び出し
- **制御**: 成長を制限する仕組みが必要

# スタックの実装方法

## 配列ベースの実装

```
トップの位置をインデックスで管理する。

利点:
- シンプルな実装
- メモリ効率が良い
- キャッシュ効率が高い

欠点:
- 固定サイズ（事前にサイズを決める必要がある）
- サイズ変更が困難
- メモリの無駄が発生する可能性

```

## 連結リストベースの実装

```
利点:
- 動的サイズ（メモリが許す限り拡張可能）
- メモリ効率が良い（必要な分だけメモリを使用する）
- サイズ制限なし

欠点:
- ポインタ管理が必要
- 若干のメモリオーバーヘッド
- キャッシュ効率が劣る場合がある

```

# スタックの応用例

## 1. 関数呼び出しの管理（コールスタック）

- **コールスタック**: プログラムが関数を呼び出す際、呼び出し元の情報（リターンアドレスやローカル変数）がコールスタックにプッシュされる
- **関数終了**: 関数が終了すると、その情報がポップされ、実行が呼び出し元に戻る
- **再帰関数**: 再帰関数の実現もこの仕組みに基づいている
- **ローカル変数**: 各関数のスコープを管理
- **例外処理**: エラーハンドリングの制御フロー

## 2. 数式の処理と計算

- **中置記法 → 後置記法**: `(3 + 4) * 2` → `3 4 + 2 *` への変換
- **後置記法の評価**: `3 4 + 2 *` のような記法の計算
- **演算子の優先順位**: 中置記法から後置記法への変換で使用
- **括弧のマッチング**: プログラムコードの構文チェック（`()`, `[]`, `{}` の対応関係）
- **計算機**: 電卓の内部処理での式評価

## 3. アルゴリズムでの活用

### バックトラッキングアルゴリズム

- **経路探索**: 深く探索し、行き止まりになったら前の分岐点に戻って別の経路を試す
- **分岐点記録**: たどってきた経路の分岐点をスタックに記録
- **迷路解法**: 効率的なバックトラックが可能

### 深度優先探索（DFS）

- **グラフ・木の探索**: バックトラッキングを実現
- **実装**: 再帰の代替としてスタックを使用

## 4. プログラム言語処理

- **括弧マッチング**: エディタの機能
  - 括弧の対応関係をチェックする際に用いられる。
- **構文解析**: コンパイラ・インタープリター
  - ソースコードを解析する際、括弧マッチンをしたり、中置記法の数式を後置記法(逆ポーランド記法)に変換してソースコードを評価したりするためにスタックが利用される
- **undo/redo**: テキストエディタの機能
  - スタックに push したユーザーの操作をもとに、「元に戻す」が実行されると、スタックの操作を pop して逆の処理を適用する

## 5. ユーザーインターフェース

### Undo/Redo 機能

- **テキストエディタ**: ユーザーの編集操作をスタックにプッシュ
- **画像編集ソフト**: 「元に戻す」が実行されると、スタックから操作をポップして逆の処理を適用
- **状態管理**: アプリケーションの状態変更履歴

### ブラウザ機能

- **履歴管理**: 戻るボタンの実装
- **ページナビゲーション**: 訪問ページの履歴をスタックで管理

## 6. メモリ管理

- **ガベージコレクション**: 参照の追跡
- **スコープ管理**: 変数の生存期間管理
- **リソース管理**: ファイルハンドルやネットワーク接続の管理

# 他のデータ構造との比較

| 操作                 | スタック | キュー | 配列     | 連結リスト |
| -------------------- | -------- | ------ | -------- | ---------- |
| **末尾追加**         | O(1)     | O(1)   | O(1)平均 | O(1)       |
| **末尾削除**         | O(1)     | -      | O(1)     | O(n)       |
| **先頭削除**         | -        | O(1)   | O(n)     | O(1)       |
| **ランダムアクセス** | O(n)     | O(n)   | O(1)     | O(n)       |
| **検索**             | O(n)     | O(n)   | O(n)     | O(n)       |
| **メモリ使用量**     | 低い     | 低い   | 低い     | 中程度     |

スタックは、LIFO の性質を活かした処理に特化したデータ構造で、特定の用途では非常に効率的です。関数呼び出し、式の評価、アルゴリズムの実装など、多くの場面で基本的かつ重要な役割を果たします。
