# スタック（Stack）とは

スタックは、LIFO（Last In, First Out：後入れ先出し）の原則に従ってデータを管理する線形データ構造です。最後に追加された要素が最初に取り出される特性を持ちます。

**最大の利点は、要素の追加・削除・参照がすべて O(1)の一定時間で実行できることです。** この高速性により、関数呼び出しの管理、式の評価、深度優先探索など、多くのアルゴリズムの基盤として活用されています。

## 基本的な特徴

- **LIFO 原則**: 最後に入れたものが最初に出る
- **単一アクセスポイント**: トップ（先頭）からのみアクセス可能
- **動的サイズ**: 実行時にサイズを変更可能
- **順序性**: 要素の挿入順序を逆順で取り出す
- **制限されたアクセス**: 中間要素への直接アクセス不可

## スタックの概念図

```
    ↓ push(要素の追加)
┌─────────┐
│    4    │ ← top（トップ）
├─────────┤
│    3    │
├─────────┤
│    2    │
├─────────┤
│    1    │ ← bottom（ボトム）
└─────────┘
    ↑ pop（要素の取り出し）
```

# 行える処理

## 基本操作

### Push（プッシュ）- 要素の追加

- **機能**: スタックの最上部に新しい要素を追加
- **計算量**: O(1)
- **戻り値**: なし（void）

### Pop（ポップ）- 要素の取り出し

- **機能**: スタックの最上部から要素を取り出して削除
- **計算量**: O(1)
- **戻り値**: 取り出した要素（スタックが空の場合はエラー）

### Peek/Top（ピーク/トップ）- 要素の参照

- **機能**: スタックの最上部の要素を削除せずに参照
- **計算量**: O(1)
- **戻り値**: 最上部の要素（スタックが空の場合はエラー）

### IsEmpty（空判定）

- **機能**: スタックが空かどうかを確認
- **計算量**: O(1)
- **戻り値**: 空の場合 true、そうでなければ false

### Size（サイズ取得）

- **機能**: スタック内の要素数を取得
- **計算量**: O(1)
- **戻り値**: 要素数（整数）

## 補助操作

### Clear（クリア）

- **機能**: スタックのすべての要素を削除
- **計算量**: O(n) または O(1)（実装による）

### IsFull（満杯判定）

- **機能**: 固定サイズスタックが満杯かどうかを確認
- **計算量**: O(1)
- **適用**: 配列ベースの固定サイズスタックのみ

# 得意な処理（効率的な操作）

## トップ要素への高速アクセス

- **計算量**: **O(1)**
- 最上部の要素に対する操作は常に一定時間
- インデックス計算や検索が不要

## 要素の追加・削除

- **計算量**: **O(1)**
- トップからの操作のみなので高速
- 他の要素への影響なし

## 深度優先探索（DFS）

- **用途**: 木やグラフの探索
- **特徴**: 自然にバックトラッキングを実現
- **実装**: 再帰の代替としてスタックを使用

## 関数呼び出しの管理

- **コールスタック**: 関数の呼び出し履歴を管理
- **ローカル変数**: 各関数のスコープを管理
- **戻りアドレス**: 関数終了後の戻り先を記録

## 括弧のマッチング

- **用途**: プログラムコードの構文チェック
- **例**: `()`, `[]`, `{}` の対応関係をチェック
- **実装**: 開き括弧を push、閉じ括弧で pop

## 式の評価

- **後置記法**: `3 4 + 2 *` のような記法の計算
- **演算子の優先順位**: 中置記法から後置記法への変換
- **計算機**: 電卓の内部処理

# 苦手な処理（非効率的な操作）

## 中間要素へのアクセス

- **計算量**: **O(n)**
- トップ以外の要素にアクセスするには、上の要素をすべて取り出す必要
- ランダムアクセスが不可能

## 要素の検索

- **計算量**: **O(n)**
- 特定の値を持つ要素を探すには、順次 pop 操作が必要
- 検索後にスタックを元の状態に戻すのが困難

## 中間位置での挿入・削除

- **計算量**: **O(n)**
- 目的の位置まで要素を取り出し、操作後に戻す必要
- スタックの基本概念に反する操作

## 全要素の表示

- **計算量**: **O(n)**
- すべての要素を確認するには、スタックを破壊するか別の構造が必要
- 非破壊的な走査が困難

## 底部（ボトム）への操作

- **計算量**: **O(n)**
- 最下部の要素への操作は最も非効率
- すべての上位要素を一時的に退避する必要

## サイズ制限のない成長

- **メモリ**: 無制限に成長する可能性
- **スタックオーバーフロー**: メモリ不足や再帰の深すぎる呼び出し
- **制御**: 成長を制限する仕組みが必要

# ユースケース

- **関数呼び出しスタック**: プログラムが関数を呼び出す際、呼び出し元の情報(リターンアド
  レスやローカル変数)がコールスタックにプッシュされる。関数が終了すると、その情報
  がポップされ、実行が呼び出し元に戻る。再帰関数の実現もこの仕組みに基づいて
  いる。
- **元に戻す(Undo)機能**: テキストエディタや画像編集ソフトでは、ユーザーの操作をスタックに push。「元に戻す」が実行されると、スタックから操作を pop して逆の処理を適用する。
- **構文解析(Parsing)**: コンパイラがソースコードを解析する際、括弧やブレースの対応関係をチェックしたり、中置記法の数式を後置記法(逆ポーランド記法)に変換して評価したりするためにスタックが利用される。
- **バックトラッキングアルゴリズム**: 深さ優先探索(DFS)や迷路の探索問題のように、ある経路を深く探索し、行き止まりになったら前の分岐点に戻って別の経路を試すアルゴリズムでは、たどってきた経路の分岐点をスタックに記録しておくことで、効率的なバックトラックが可能になる。

# 他のデータ構造との関係

## 配列との関係

- **実装**: 配列を使ってスタックを実装可能
- **インデックス管理**: トップの位置をインデックスで管理
- **固定サイズ**: 配列ベースは事前にサイズを決める必要がある

## 連結リストとの関係

- **実装**: 連結リストでもスタックを実装可能
- **動的サイズ**: メモリが許す限り拡張可能
- **メモリ効率**: 必要な分だけメモリを使用

## キューとの対比

- **スタック**: LIFO（後入れ先出し）
- **キュー**: FIFO（先入れ先出し）
- **用途**: 異なるアルゴリズムで使い分け

## 木構造との関係

- **深度優先探索（DFS）**: スタックを使って実装
- **関数呼び出し**: コールスタックとして使用
- **式の評価**: 構文解析でスタックを活用

# スタックの実装方法

## 配列ベースの実装

```
利点:
- シンプルな実装
- メモリ効率が良い
- キャッシュ効率が高い

欠点:
- 固定サイズ
- サイズ変更が困難
- メモリの無駄が発生する可能性
```

## 連結リストベースの実装

```
利点:
- 動的サイズ
- メモリ効率が良い
- サイズ制限なし

欠点:
- ポインタ管理が必要
- 若干のメモリオーバーヘッド
- キャッシュ効率が劣る場合がある
```

# スタックの応用例

## 1. 関数呼び出しの管理

- **コールスタック**: プログラムの実行制御
- **ローカル変数**: スコープ管理
- **例外処理**: エラーハンドリング

## 2. 数式の処理

- **中置記法 → 後置記法**: `(3 + 4) * 2` → `3 4 + 2 *`
- **計算**: 後置記法の評価
- **括弧**: 演算の優先順位管理

## 3. アルゴリズム

経路を深く探索するとき、行き止まりになったら前の分岐点に戻って別の経路を試すアルゴリズムで用いられる。
辿ってきた経路の分岐点をスタックに記録する。

- **深度優先探索（DFS）**: グラフ・木の探索
- **バックトラッキング**: 解の探索
- **迷路解法**: 経路探索

## 4. プログラム言語処理

- **構文解析**: コンパイラ・インタープリター
- **括弧マッチング**: エディタの機能
- **undo/redo**: テキストエディタの機能
  - スタックに push したユーザーの操作をもとに、「元に戻す」が実行されると、スタックの操作を pop して逆の処理を適用する

## 5. ブラウザ

- **履歴管理**: 戻るボタンの実装
- **JavaScript**: 実行コンテキストの管理

# 他のデータ構造との比較

| 操作                 | スタック | キュー | 配列     | 連結リスト |
| -------------------- | -------- | ------ | -------- | ---------- |
| **末尾追加**         | O(1)     | O(1)   | O(1)平均 | O(1)       |
| **末尾削除**         | O(1)     | -      | O(1)     | O(n)       |
| **先頭削除**         | -        | O(1)   | O(n)     | O(1)       |
| **ランダムアクセス** | O(n)     | O(n)   | O(1)     | O(n)       |
| **検索**             | O(n)     | O(n)   | O(n)     | O(n)       |
| **メモリ使用量**     | 低い     | 低い   | 低い     | 中程度     |

スタックは、LIFO の性質を活かした処理に特化したデータ構造で、特定の用途では非常に効率的です。関数呼び出し、式の評価、アルゴリズムの実装など、多くの場面で基本的かつ重要な役割を果たします。
