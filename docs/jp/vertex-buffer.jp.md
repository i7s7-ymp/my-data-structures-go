# Vertex Buffer（頂点バッファ）

## 概要

**Vertex Buffer（頂点バッファ）**は、3D グラフィックスやゲーム開発などのコンピュータグラフィックスのレンダリングパイプラインにおいて、頂点データ（位置、法線、色、テクスチャ座標など）を CPU から GPU（Graphics Processing Unit）へ効率的に転送するために特化したメモリバッファである。

---

## レンダリングパイプライン

3D の仮想世界（3D モデル、ライト、カメラなど）を 2D 画面上のピクセルに変換するための一連の処理工程のこと。

3D グラフィックスでは以下の変換が必要であり、これを段階的に行うのがレンダリングパイプラインである。

- 3D 空間の頂点座標を 2D 画面のピクセルに変換する
- 3D オブジェクトの形状・材質・照明を最終的な色・明度に変換する

典型的なレンダリングパイプラインは以下の通り。
Vertex Buffer は最初の頂点処理の工程に関わってくる。

```code
【入力】3Dモデルデータ（頂点、テクスチャ、マテリアルなど）
    ↓
┌─────────────────────────────────────┐
│ 1. 頂点処理（Vertex Processing）    │
│   ・座標変換（ワールド→ビュー→射影） │
│   ・頂点シェーダーの実行             │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│ 2. プリミティブ組み立て              │
│   ・頂点を三角形やラインに組み立て   │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│ 3. ラスタライゼーション              │
│   ・三角形を画面上のピクセルに分割   │
│   ・補間処理（色、法線、UVなど）     │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│ 4. フラグメント処理                  │
│   ・ピクセルシェーダーの実行         │
│   ・テクスチャサンプリング           │
│   ・ライティング計算                 │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│ 5. ピクセル出力                      │
│   ・深度テスト（Z-buffer）           │
│   ・アルファブレンディング           │
│   ・フレームバッファへの書き込み     │
└─────────────────────────────────────┘
    ↓
【出力】2D画面上の最終画像
```

---

## 特徴

- **連続したメモリ領域**に頂点データを格納し、高速なアクセスと転送が可能
- 頂点ごとに複数の属性（位置、色、法線、UV など）を持てる
- GPU と CPU 間で効率的にデータをやり取りできる
- バッチ描画やインデックスバッファと組み合わせて描画効率を向上

---

## 注意

Vertex Buffer はデータ構造自体が論理的な特性として定義されるのではない。構造だけで言えば、連続した配列である。Vertex Buffer は GPU のメモリアクセスパターンを最適化するために、データをその配列にどう配置するか（データレイアウト）、それをどのように管理するか（メモリ管理）を検討することが重要である。

- **データレイアウト**
  - **インターリープ形式（Interleaved）**: 一つの頂点を構成するすべての属性をメモリ上で隣接して格納する。これは、一つの頂点シェーダーが処理するデータがメモリ上で近接するため、GPU のキャッシュ効率の観点から一般的に好まれる。
  - **分離形式(Separate)**: 各属性をそれぞれ別のバッファに格納する（例：全頂点の位置座標を持つバッファ、全頂点の色情報を持つバッファ）。特定の属性のみを更新する場合などに利点がある。
- **メモリ管理**
  - **静的バッファ**: ゲームのステージや建築モデルなど、一度ロードされたら変化しないジオメトリに使用される。データは GPU に一度だけアップロードされる。
  - **動的バッファ**: パーティクルシステムやアニメーションするキャラクターなど、フレームごとに頻繁にデータが更新されるジオメトリに使用される。
  - **ストリーミングバッファ**: データが一度書き込まれ、数フレームの間だけ使用された後に破棄されるようなケース（例：UI 要素など）に用いられる。

---

## 構成要素

- **頂点配列（Vertex Array）**: 頂点ごとの属性値（例：位置、色、法線、UV 座標など）の配列
- **頂点フォーマット**: 各頂点が持つ属性の型や順序（例：float32[3]位置, float32[3]法線, float32[2]UV）
- **バッファサイズ**: 頂点数 ×1 頂点あたりのデータサイズ
- **（オプション）インデックスバッファ**: 頂点の再利用や描画効率化のためのインデックス配列

---

## ユースケース

- 3D ゲームや CG レンダリングエンジンでのメッシュ描画
- WebGL/OpenGL/DirectX/Vulkan などのグラフィックス API での描画処理
- CAD や可視化ツールでの大規模な頂点データ管理
- パーティクルシステムやスプライト描画

# 実装

## 一般的な実装方法

- **固定長配列や構造体配列**で頂点データを管理
- GPU 側にバッファ（VBO: Vertex Buffer Object）として転送
- 頂点ごとに属性を構造体でまとめる
- バッファの生成・更新・削除は API（OpenGL, DirectX, Vulkan 等）で管理

## Go での実装方法

ゼロから実装して利用することはほぼない。
OpenGL, Vulkan, WebGPU, DirectX などの低レベルグラフィックス API へのバイディングを提供する Go ライブラリを利用することが多い。

### フルスクラッチ実装例

```go
type Vertex struct {
    Position [3]float32
    Normal   [3]float32
    UV       [2]float32
}

type VertexBuffer struct {
    Vertices []Vertex
}

func NewVertexBuffer(size int) *VertexBuffer {
    return &VertexBuffer{
        Vertices: make([]Vertex, size),
    }
}

func (vb *VertexBuffer) SetVertex(i int, v Vertex) {
    vb.Vertices[i] = v
}
```

### ライブラリ利用例

Go では OpenGL バインディング（[go-gl/glfw](https://github.com/go-gl/glfw)、[go-gl/gl](https://github.com/go-gl/gl)など）や 3D エンジン（`engo`, `raylib-go`など）を利用して GPU バッファを管理可能。

以下に仮想的な Go のグラフィックス API ラッパーを用いて、概念的な実装フローを示す。頂点データを定義し、それを GPU メモリに転送し、シェーダーがそのデータをどのように解釈すべきか（各属性のオフセットやストライド）を指示し、最終的に描画を実行する一連の流れを示している。

```go

// 1. Goのスライスとして頂点データを定義
type Vertex struct {
    Position float32
    Color    float32
}
vertices :=Vertex{
    {Position: float32{-0.5, -0.5, 0.0}, Color: float32{1.0, 0.0, 0.0}},
    {Position: float32{0.5, -0.5, 0.0}, Color: float32{0.0, 1.0, 0.0}},
    {Position: float32{0.0, 0.5, 0.0}, Color: float32{0.0, 0.0, 1.0}},
}

// 2. GPU上にバッファオブジェクトを作成
vbo := graphicsAPI.CreateBuffer()

// 3. 作成したバッファを現在の頂点バッファとして束縛（バインド）
graphicsAPI.BindBuffer(graphicsAPI.VertexBuffer, vbo)

// 4. GoのスライスデータをGPUバッファにアップロード
graphicsAPI.BufferData(graphicsAPI.VertexBuffer, vertices, graphicsAPI.StaticDraw)

// 5. 頂点属性のレイアウトを定義
// 頂点シェーダーの入力ロケーション0に位置情報を設定
graphicsAPI.VertexAttribPointer(0, 3, graphicsAPI.Float, false, unsafe.Sizeof(Vertex{}), 0)
graphicsAPI.EnableVertexAttribArray(0)
// 頂点シェーダーの入力ロケーション1に色情報を設定
graphicsAPI.VertexAttribPointer(1, 3, graphicsAPI.Float, false, unsafe.Sizeof(Vertex{}),

unsafe.Offsetof(Vertex{}.Color))
graphicsAPI.EnableVertexAttribArray(1)

//... レンダリングループ内で...
// 6. Vertex Bufferを使用して描画コマンドを発行
graphicsAPI.DrawArrays(graphicsAPI.Triangles, 0, 3)

```

# 応用

- **インスタンシング**: 同じ形状を複数回描画する際に、頂点バッファを使い回す
- **ダイナミックバッファ**: アニメーションや動的な頂点変形に対応
- **ストリーミング**: 大量の頂点データを逐次 GPU に送る用途
- **複数属性の管理**: 位置・色・法線・UV などを柔軟に切り替え・拡張

# 類似データ構造・アルゴリズムとのトレードオフ

| データ構造               | 特徴・用途                                         | トレードオフ                                       |
| ------------------------ | -------------------------------------------------- | -------------------------------------------------- |
| **Vertex Buffer**        | 頂点データを連続メモリで管理、GPU 転送に最適       | 柔軟性は低いが高速・省メモリ                       |
| **構造体配列（AoS）**    | 各頂点を構造体で管理し、属性ごとにアクセスしやすい | キャッシュ効率は良いが属性単位の操作は遅い場合あり |
| **属性配列（SoA）**      | 属性ごとに配列を分ける（位置配列、色配列など）     | 属性単位の操作が高速、頂点単位の操作は遅い場合あり |
| **インデックスバッファ** | 頂点の再利用によるメモリ削減・描画効率化           | 実装がやや複雑になる                               |
